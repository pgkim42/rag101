# 6. 생성: 글을 붙여 답하기

> 검색한 글을 지시와 함께 질문 앞에 붙이면, 생성 모델은 그 글로 답한다. 맞는 글이 칸에 들어가면 고를 줄 알고, 답이 없으면 「모른다」고도 한다. 위험한 건 「반쯤 맞는 글」이다.

## 이 장에서 알게 되는 것

- 증강된 프롬프트가 어떻게 생겼는지
- 생성 모델을 코드에 연결하는 법
- 글을 몇 편 붙여야 하는지 (실험)
- 답이 코퍼스에 없는 질문에서 검색과 생성이 어떻게 구는지 (실험)

## 왜 필요한가

검색은 글을 골라 줄 뿐 답을 쓰지 않는다. 고른 글을 읽고 문장으로 답하는 일은 생성 모델이 한다. 이때 두 가지가 문제다.

1. 글을 몇 편 붙여야 하나? 적으면 정답 글을 놓치고, 많으면 상관없는 글이 섞인다.
2. 질문의 답이 코퍼스에 아예 없으면? 검색은 늘 「가장 가까운」 글을 내놓는다. 아무리 멀어도.

## 원리: 증강된 프롬프트

`answer.py`의 `build_prompt()`는 이런 입력을 만든다.

```text
아래 글만 근거로 답하세요. 글에 없는 내용은 모른다고 하세요.
답에 쓴 글의 번호를 [1]처럼 붙이고, 질문과 같은 언어로 답하세요.

글:
[1] 방화벽
방화벽은 정해진 규칙에 따라 들어오고 나가는 통신을 감시하고 제어하는 ...

[2] HTTP와 HTTPS
...

[3] VPN
...

질문: 허가되지 않은 네트워크 통신을 무엇이 막나?
```

지시 두 줄이 각각 하는 일이 있다.

| 지시 | 왜 |
| --- | --- |
| 아래 글만 근거로, 없으면 모른다고 | 모델이 기억으로 지어내지 않게 한다. 답이 없는 질문에서 이 줄이 일한다(아래 실험) |
| 글 번호를 [1]처럼 | 어느 글을 근거로 썼는지 보이게 한다. 여러 편 붙였을 때 특히 필요하다 |
| 질문과 같은 언어로 | 영어 글을 붙여도 한국어로 물으면 한국어로 답하게 한다 |

## 생성 모델 연결하기

`answer.py`는 OpenAI 형식(chat completions)을 쓰는 엔드포인트면 무엇이든 쓴다. 주소, 키, 모델 이름은 `.env`에서 읽는다.

```bash
cp .env.example .env
```

```text
OPENAI_BASE_URL=http://127.0.0.1:8317/v1   # 로컬 CLIProxyAPI를 쓸 때. OpenAI를 바로 쓰면 이 줄을 지운다
OPENAI_API_KEY=여기에-키
RAG_LLM_MODEL=gpt-6-luna
```

- 이 저장소는 API 키 대신 로컬 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)를 거쳐 `gpt-6-luna`를 부른다. 구독 계정을 OpenAI 형식 API로 열어 주는 도구다. 구독은 원래 앱이나 CLI로 쓰라고 파는 것이라, 이렇게 API처럼 쓰는 건 약관상 회색지대다. 혼자 공부하는 데만 쓰자.
- OpenAI 키가 있으면 `OPENAI_BASE_URL` 줄을 지우고 키만 넣으면 된다.
- 키가 없으면 `answer.py`는 바로 안내 문구를 내고 종료 코드 1로 끝난다.
- `.env`는 `.gitignore`에 들어 있다. 키를 커밋하지 말자.

## 직접 해 보기 1: 몇 편을 붙일까

```bash
.venv/bin/python answer.py --k 1 "허가되지 않은 네트워크 통신을 무엇이 막나?"
.venv/bin/python answer.py --k 3 "허가되지 않은 네트워크 통신을 무엇이 막나?"
.venv/bin/python answer.py --method dense --k 1 "허가되지 않은 네트워크 통신을 무엇이 막나?"
```

검색이 임베딩뿐이던 때(`--method dense`), 검색이 틀린 세 질문을 `gpt-6-luna`로 돌린 결과다.

| 질문 | `--k 1` (1등 글만) | `--k 3` |
| --- | --- | --- |
| 허가되지 않은 네트워크 통신을 무엇이 막나? | VPN 글로 「통신을 암호화한다」고 답함 (틀림) | 「방화벽이 기준에 맞지 않는 연결을 차단한다 [2]」 |
| 바닷물은 왜 하루에 두 번 올랐다 내리나? | 「글에 나와 있지 않다」 | 「달의 중력과 지구 자전 때문 [2]」 |
| 돈으로 살 수 있는 양이 시간이 갈수록 줄어드는 이유는? | 「글만으로는 알 수 없다」 | 「인플레이션으로 구매력이 줄기 때문 [2]」 |

### 결과 읽기

- **3편이면 다 맞았다.** 정답 글이 늘 2등이었고, 모델은 `[2]`를 골라 썼다. 4장의 「Recall@3 = 1.000」이 바로 이 뜻이다. 줄 세우기가 조금 틀려도 정답이 칸에 들어가기만 하면, 모델이 고를 줄 안다. 그래서 `--k` 기본값은 3이다.
- **1편이면 두 가지로 실패한다.** 밀물·인플레이션 질문에서는 「모른다」고 했다. 글과 질문이 확실히 어긋나서 모델이 알아챘다. 방화벽 질문에서는 VPN 글로 그럴듯한 틀린 답을 만들었다. VPN 글도 「통신」을 다루고, 「통신 내용을 읽지 못하게 한다」처럼 무언가를 막는 이야기도 하기 때문이다. **가장 위험한 건 엉뚱한 글이 아니라 반쯤 맞는 글이다.**
- 검색을 `rerank`로 바꾼 뒤에는 방화벽 질문도 `--k 1`에서 방화벽 글을 1등으로 받고 「방화벽이 막습니다. [1]」이라고 답한다.
- 그렇다고 많이 붙일수록 좋진 않다. 상관없는 글이 섞일수록 모델이 그걸 근거로 집을 기회도 는다. 이 15편은 짧아서 3편이 부담이 없을 뿐이다.

## 직접 해 보기 2: 답이 없는 질문

```bash
.venv/bin/python -m labs.unanswerable             # 검색 점수 + 생성 모델 답 (키 필요)
.venv/bin/python -m labs.unanswerable --skip-llm  # 검색 점수만
```

`labs/unanswerable.py`는 질문 세 묶음을 넣어 본다.

| 묶음 | 예 | 개수 |
| --- | --- | --- |
| 답 있음 | 정답표 15문항 | 15 |
| 주제 밖 | 김치찌개는 어떻게 끓이나? / 블랙홀은 어떻게 생기나? | 8 |
| 주제는 같지만 답 없음 | 방화벽 제품은 어떤 회사가 만드나? / 백신 부작용에는 어떤 것이 있나? | 6 |

세 번째 묶음이 핵심이다. 15편의 주제(방화벽, 백신, DNS …)를 건드리지만, 그 글에 답이 적혀 있지 않은 질문이다.

### 결과 읽기 1: 검색 점수로 거를 수 있나

질문마다 1등 글의 점수를 모았다.

| 묶음 | dense (코사인) | rerank (재순위화 점수) |
| --- | --- | --- |
| 답 있음 | 0.363 ~ 0.875 | −2.731 ~ 9.944 |
| 주제 밖 | 0.155 ~ 0.347 | −5.415 ~ −2.916 |
| 주제는 같지만 답 없음 | 0.261 ~ 0.781 | −5.256 ~ 2.272 |

「1등 점수가 문턱보다 낮으면 생성 모델을 부르지 말고 '관련 글이 없다'고 하자」는 생각을 해 볼 수 있다. 문턱을 「답 있음」 중 가장 낮은 점수로 두면 이렇게 된다.

| 방식 | 문턱 | 주제 밖 통과 | 같은 주제·답 없음 통과 |
| --- | --- | --- | --- |
| dense | 0.363 | 0/8 | 5/6 |
| rerank | −2.731 | 0/8 | 3/6 |

- **주제 밖은 깔끔히 걸러진다.** 하지만 여유가 아주 작다. dense에서 주제 밖 최고점 0.347과 답 있음 최저점 0.363의 차이가 0.016이다. 질문이 몇 개만 늘어도 겹칠 수 있다.
- **같은 주제·답 없음은 못 거른다.** 검색 점수는 「주제가 맞는가」를 재지, 「답이 들어 있는가」를 재지 않는다. 「DNS 서버 주소는 어떻게 바꾸나?」는 rerank에서 2.272로, 답 있는 질문들보다 높았다. DNS 글이 「이름을 IP 주소로 바꾼다」는 이야기라 「주소」, 「바꾸다」가 잘 맞아서다. 답은 없는데도.

### 결과 읽기 2: 생성 모델은 모른다고 하나

rerank 위 3편을 붙여 `gpt-6-luna`에게 물었다.

| 묶음 | 「모른다」 쪽으로 답한 수 |
| --- | --- |
| 주제 밖 | 8/8 |
| 주제는 같지만 답 없음 | 6/6 |
| 답 있음 | 1/15 (잘못 센 것, 아래) |

답의 예:

```text
방화벽 제품은 어떤 회사가 만드나?
  → 글에는 방화벽 제품을 만드는 회사가 나와 있지 않습니다. 모릅니다. [1]
DNS 서버 주소는 어떻게 바꾸나?
  → 글에는 DNS 서버 주소를 바꾸는 방법이 나와 있지 않습니다. [1]
```

검색 점수로 못 거른 질문까지, 「글에 없으면 모른다고 하라」는 한 줄이 다 막았다. 검색이 걸러 주지 못하는 마지막 부분을 지시가 맡은 셈이다.

### 「답 있음 1/15」는 측정 도구의 실수다

`labs/unanswerable.py`는 답에 「모르」, 「알 수 없」, 「나와 있지 않」 같은 말이 있으면 「모른다」로 센다. 그런데 이 답이 걸렸다.

```text
직각삼각형에서 모르는 변의 길이는 어떻게 구하나?
  → 직각삼각형의 두 변을 알면 피타고라스 정리 \(a^2+b^2=c^2\)를 이용해 모르는 변의 길이를 계산합니다. [1]
```

맞는 답인데, 질문에 있던 「**모르**는 변」이 답에 그대로 나와서 「모른다」로 세어졌다. 낱말로 판정하는 건 이렇게 쉽게 틀린다. 그래서 스크립트는 답 전문을 같이 출력한다. 제대로 하려면 사람이 읽거나, 다른 모델에게 「이 답은 거절인가?」를 따로 묻는 방법(LLM 판정)을 쓴다. 이것도 완벽하지는 않아서 판정 결과를 사람이 일부 확인한다.

생성 모델은 같은 입력에도 매번 조금씩 다른 문장을 쓴다. 다시 돌리면 숫자가 한두 개 달라질 수 있다.

## 자주 하는 오해

- **「검색 점수 문턱만 잘 잡으면 헛소리를 막는다」**: 주제 밖 질문은 막지만, 같은 주제에 답만 없는 질문은 못 막는다. 문턱과 지시를 같이 쓴다.
- **「'모르면 모른다고 하라'고 쓰면 늘 지킨다」**: 이 실험에서는 잘 지켰다. 하지만 반쯤 맞는 글 한 편만 줬을 때(방화벽 `--k 1`)는 안 지켰다. 지시는 좋은 글과 같이 있을 때 잘 통한다.
- **「글을 많이 붙이면 안전하다」**: 정답이 들어갈 확률은 오르지만, 상관없는 글이 근거로 쓰일 확률도 오른다.

## 정리

- 증강 = 지시 + 고른 글 + 질문. 지시가 「글만 근거로」, 「없으면 모른다」, 「번호 달기」를 맡는다.
- 정답이 칸에 들어가면 모델이 고른다. 그래서 Recall@k와 `--k`를 같이 본다.
- 가장 위험한 건 반쯤 맞는 글이다. 그럴듯한 틀린 답이 나온다.
- 검색 점수는 「주제가 맞나」만 잰다. 「답이 있나」는 생성 단계의 지시가 마지막으로 막는다.
- 낱말로 답을 판정하면 틀린다. 답 전문을 같이 본다.

## 연습 문제

1. `answer.py`의 `INSTRUCTION`에서 「글에 없는 내용은 모른다고 하세요.」를 지우고 `labs.unanswerable`을 다시 돌려 보자. 「주제는 같지만 답 없음」 묶음의 답이 어떻게 바뀌나?
2. `answer.py`에 `--min-score` 옵션을 만들어, 1등 점수가 그보다 낮으면 생성 모델을 부르지 않고 「관련 글을 찾지 못했습니다」를 내게 해 보자. 문턱은 위 표를 보고 정하되, 4장의 「과적합」도 생각하자.
3. `labs/unanswerable.py`의 `REFUSAL_WORDS`에서 `"모르"`를 빼면 「답 있음」의 오판이 사라지나? 대신 놓치는 거절이 생기나?
