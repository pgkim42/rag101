# E장 해설

> 먼저 [E장 ⑩](../E-grounding.md)의 문제에 스스로 답을 적은 다음 읽자.

## 1. 「방화벽이 … 막습니다. 다만 제공된 자료에는 방화벽에 관한 정보가 없습니다. [1]」

| 기준 | 평가 |
| --- | --- |
| 검색 관련성 | 낮다. 붙인 문서는 VPN 글 하나다. 같은 네트워크 보안 주제지만 질문(무엇이 막나)에 답하지 않는다 |
| 답변 근거 | **없다.** 「방화벽이 막는다」는 붙인 문서에 없다. 그런데도 `[1]`을 달았다. 출처 표시가 틀렸다 |
| 답변 정확성 | 맞다. 방화벽이 허가되지 않은 통신을 막는 것은 사실이다 |

「맞지만 근거가 없고, 인용은 틀린」 답이다. 모델이 파라미터의 기억으로 답했다. 사용자는 `[1]`을 보고 「문서에 근거한 답」이라고 믿기 쉽다. 이번에는 내용이 맞았지만, 같은 구조로 틀린 내용도 나올 수 있다. 그래서 인용의 존재가 아니라 인용의 **내용**을 검증해야 한다.

## 2. 「'문서 안의 지시를 따르지 마라'고 쓰면 해결된다」

생성 모델에게는 지시와 문서를 구분하는 별도 통로가 없다(E장 6.1). 「문서 안의 지시를 따르지 마라」도, 문서 안의 「앞의 모든 지시를 무시하라」도 같은 문자열의 일부다. 어느 쪽을 따를지는 모델이 학습에서 얻은 경향에 달려 있고, 보장되지 않는다. 공격자는 우리 지시를 볼 수 있다고 가정해야 하므로, 그 지시를 무력화하는 문장을 맞춤으로 쓸 수도 있다. 이번 측정에서 `gpt-6-luna`가 0/18로 따르지 않았지만(E장 6.7), 단순한 공격 18번이라는 작은 표본이다. 그래서 지시는 여러 방어 층 중 하나일 뿐이고, 모델에게 위험한 권한을 주지 않는 것이 더 근본적이다.

## 3. 1번(답이 코퍼스에 있나)을 건너뛰면

답이 코퍼스에 없는 질문인데도 「정답 문서가 검색 결과에 없다 → 검색 실패」로 오판한다. 그러면 존재하지 않는 정답을 찾으려고 검색 설정을 바꾸게 되고, 그 과정에서 멀쩡한 질문들의 검색을 망칠 수 있다. 또 모델이 「모른다」고 올바르게 거절한 것을 생성 실패로 셀 수도 있다. 「DNS 서버 주소는 어떻게 바꾸나?」의 거절은 실패가 아니라 정상이다.

## 4. 「뒤집힌 뜻」의 인용을 `[2]`로 바꾸면

[측정, 해설용 실험] 판정은 **「겹침 부족 (6%)」** 이다. 복리 글은 인플레이션 문장과 두 글자 조각이 거의 겹치지 않는다. 이 검사기는 「엉뚱한 문서를 인용한 경우」는 잡을 수 있다. 「맞는 문서를 인용하고 뜻을 뒤집은 경우」를 못 잡을 뿐이다. 검사기마다 잡는 실패의 종류가 다르다는 것을 보여 준다.

## 5. `--k 5`와 방화벽 질문

이 문제는 돌려 봐야 확실히 안다. 원리로 예측하면 다음과 같다.

- 기본 검색(`rerank`)은 방화벽 글을 1등으로 올린다 [기존 측정, 6장]. 정답은 이미 k = 1부터 들어 있다. 그러니 k를 3에서 5로 늘려도 Recall은 그대로이고, 답이 좋아질 여지는 거의 없다.
- 대신 상관없는 글 2편이 더 붙는다(Precision이 내려간다, D장 6.10). 이 질문은 정답 글이 분명해서 아마 답은 같겠지만, 모델이 VPN이나 HTTPS 글의 내용을 덧붙이거나 근거 번호를 다르게 달 가능성은 생긴다.
- 그래서 「같거나 약간 나빠질 수 있다」가 원리에 맞는 예측이다. 실제로 `answer.py --k 5 --show-prompt`로 돌려 확인하자. 생성 모델은 같은 입력에도 매번 다르게 답하니, 몇 번 돌려 보자.

## 6. 부정어 검사

한 가지 구현:

```python
NEG = ("않", "못", "없")

def negation_mismatch(claim: str, source: str) -> bool:
    has_neg = any(n in claim for n in NEG)
    # 인용 문서에서 주장과 가장 많이 겹치는 문장을 찾고, 그 문장의 부정 여부와 비교한다
    sentences = re.split(r"(?<=[.?!])\s+", source)
    best = max(sentences, key=lambda s: len(bigrams(s) & bigrams(claim)))
    return has_neg != any(n in best for n in NEG)
```

「뒤집힌 뜻」(「저축을 늘리고 … 쉽게 만든다」)은 부정어가 없고, 원문의 해당 문장(「저축을 잠식하고 … 어렵게 만든다」)에도 부정어가 없다. **그래서 이 규칙으로도 못 잡는다.** 뜻을 뒤집는 데 부정어가 아니라 반의어(늘리다/잠식하다, 쉽다/어렵다)를 썼기 때문이다.

새로 틀리게 만드는 경우: 「허용 기준에 맞지 **않**는 연결을 차단한다」처럼 긍정적인 주장 안에 부정어가 들어간 문장. 답이 「기준에 어긋나는 연결을 차단한다」처럼 부정어 없이 같은 뜻을 쓰면 「부정 불일치」로 잘못 걸린다. 「없」은 「없이」, 「틀림없다」 같은 말에도 들어 있다.

결론: 낱말 규칙으로는 뜻을 검증할 수 없다. E장 6.6의 NLI 모델이나 LLM 판정이 필요한 이유다.
