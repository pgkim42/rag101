# B장 해설

> 먼저 [B장 ⑩](../B-lexical.md)의 문제에 스스로 답을 적은 다음 읽자.

## 1. IDF가 문서 수로 세는 이유

IDF가 답하려는 질문은 「이 토큰이 있다는 사실이 **어느 문서인지** 얼마나 가려 주나」다. 그건 토큰이 몇 편에 퍼져 있는지로 정해진다. 한 문서 안에서 몇 번 나오는지는 「그 문서가 그 토큰에 대해 얼마나 말하나」라는 다른 질문이고, 그건 TF가 맡는다. D2의 「통신」 네 번을 df에도 4로 세면, 같은 반복을 TF와 IDF에서 두 번 반영하게 된다. 그래서 `bm25.py`는 `for term in doc`(Counter의 키, 즉 문서 안의 서로 다른 토큰)으로 df를 센다.

## 2. k1 = 0이면

식에 k1 = 0을 넣으면:

```text
IDF × tf × (0 + 1) / (tf + 0 × (...)) = IDF × tf / tf = IDF     (tf ≥ 1일 때)
```

점수는 「질문 토큰 중 문서에 **있는** 것의 IDF 합」이 된다. 몇 번 나오는지(tf)도, 문서 길이(b)도 보지 않는다. b는 k1에 곱해져 있어서 k1 = 0이면 효과가 사라진다. 있다/없다만 보는 이진 검색에 IDF 무게를 준 것과 같다.

## 3. 「BM25는 긴 문서를 불리하게 만든다」

절반만 맞다. 더 정확히 말하면 이렇다. **같은 tf라면** 평균보다 긴 문서의 몫을 줄이고, 평균보다 짧은 문서의 몫을 늘린다. 그 정도는 b가 정한다(b = 0이면 길이를 무시). B장 6.6의 표에서 tf = 2일 때, 평균의 0.5배 길이 문서는 b = 0.75에서 1.702로 오히려 늘었다. 그리고 긴 문서가 질문 토큰을 실제로 더 많이 담고 있으면(tf가 크면) 여전히 이길 수 있다. 「길다는 이유만으로 생기는 이득을 상쇄한다」가 정확한 표현이다.

## 4. D4 = 「통신」 × 8을 추가하면

[측정, 해설용 계산] N이 3에서 4로, df(통신)이 2에서 3으로 바뀐다.

| | 전 (N = 3) | 후 (N = 4) |
| --- | --- | --- |
| df(통신) | 2 | 3 |
| ln(N/df) | 0.4055 | 0.2877 |
| BM25 IDF(통신) | 0.4700 | 0.3567 |
| BM25 IDF(방화벽) | 0.9808 | 1.2040 |
| 평균 길이 | 8.6667 | 8.5 |
| BM25(D1) | 1.8461 | **2.0355** (오름) |
| BM25(D2) | 0.7753 | **0.5851** (내림) |
| BM25(D4) | — | 0.7562 |

- 「통신」이 더 흔해져 IDF가 내려갔다. 「통신」에 기대던 D2가 내려갔다.
- 문서가 늘면서 「방화벽」은 상대적으로 더 드물어져(4편 중 1편) IDF가 올라갔다. D1이 올랐다. **다른 문서를 추가했을 뿐인데 D1의 점수가 바뀌었다.** IDF가 코퍼스 전체에 의존하기 때문이다.
- 「통신」만 여덟 번 반복한 D4(0.7562)가 D2(0.5851)를 이겼다. 포화(k1)가 있어도 반복은 어느 정도 이득이 된다. 다만 D1을 이기지는 못한다.
- `lexical.py`에서 실제로 해 보면 3부의 `assert raw == {"D1": 3, "D2": 4, "D3": 0}`에서 멈춘다. D4가 추가되어 사전의 모양이 달라졌기 때문이다. 이 assert는 「장난감 코퍼스가 바뀌었다」는 것을 알려 주는 역할을 했다.

## 5. 질문을 「방화벽 방화벽 방화벽」으로

정확히 **3배**다. `bm25.py`의 `scores()`는 `for term in terms if term in doc`으로 질문 토큰을 **중복까지 그대로** 돌며 더한다. 「방화벽」 하나가 `방화`, `화벽` 두 조각이니, 세 번 쓰면 같은 조각들이 세 번씩 더해진다. 문서 쪽 계산은 그대로라서 점수가 정확히 3배가 된다. 문서 쪽 tf에는 포화가 있지만, 질문 쪽 반복에는 포화가 없다. 원래 BM25 논문에는 질문 쪽 반복을 포화시키는 k3라는 매개변수도 있는데, 질문이 짧은 경우가 많아 대부분의 구현이 생략한다.

## 6. 세 글자 조각

[측정, 해설용 실험] `tri()`를 추가해 `--real`과 같은 방식으로 돌리면 **ko 12/15, en 12/15**다. 두 글자 조각(ko 14/15)보다 한국어가 나빠졌다.

두 힘으로 설명할 수 있다.

- **우연한 일치는 줄어든다.** 세 글자가 우연히 같을 확률은 두 글자보다 낮다(「수록」 같은 사고가 줄어든다).
- **겹쳐야 할 것도 못 겹친다.** 한국어 낱말은 짧은 것이 많다. 「차단하는」과 「차단한다」는 두 글자로는 `차단`을 공유하지만, 세 글자로는 `차단하` `단하는`과 `차단한` `단한다`라서 하나도 안 겹친다. 「통신을」과 「통신」은 세 글자로 자르면 `통신을`과 `통신`(두 글자짜리 낱말은 통째로 남는다)이라 아예 안 겹친다.

이 데이터에서는 두 번째 힘이 더 컸다. 이 결과도 15문항에서 나온 것이라 「세 글자가 늘 나쁘다」고 일반화하면 안 된다(F장).
