# F장 해설

> 먼저 [F장 ⑩](../F-evaluation.md)의 문제에 스스로 답을 적은 다음 읽자.

## 1. 정답이 하나인 정답표의 Precision@5

최댓값은 **1/5 = 0.2**다. 정답이 한 편뿐이니 상위 5편 중 정답은 많아야 1편이다. 정답을 1등에 두든 5등에 두든 P@5는 똑같이 0.2라서, 순위의 좋고 나쁨을 구분하지 못한다. 정답이 상위 5편 밖이면 0이다. 즉 이 정답표에서 P@k는 「Recall@k ÷ k」와 같아서 새 정보가 없다. 그래서 이 저장소는 Hit@1, Recall@k, MRR을 보고한다.

## 2. 「MRR 0.5 = 모든 질문에서 정답이 2등」?

아니다. MRR은 평균이라 여러 분포가 같은 값을 낸다. 반례: 질문 두 개 중 하나는 1등(RR = 1), 하나는 상위 5편 밖(RR = 0)이면 MRR = (1 + 0) / 2 = 0.5다. 정답이 2등인 질문은 하나도 없다. 그래서 4장과 `labs/score_fusion.py`는 지표와 함께 **문항별 순위**를 출력한다.

## 3. 시험용으로 다시 고르기

시험용 점수를 보고 설정을 다시 골랐으므로, 그 순간 시험용은 **개발용이 되었다.** 다시 채점한 점수는 6.6의 시뮬레이션처럼 부풀려져 있다. 할 수 있는 일은 두 가지다. (1) 새 시험용 질문을 만들어 그걸로 한 번만 채점한다. (2) 새 질문을 만들 수 없다면 「이 점수는 개발 과정에서 본 질문으로 잰 것」이라고 밝힌다.

## 4. `d2, d4, d1, d3, d5`, 정답 d1(2점), d2(1점)

[측정, 해설용 계산과 일치]

```text
Hit@1 = 1      (1등 d2가 정답이다. 부분적인 답이어도 정답이다)
P@3   = 2/3 = 0.667  (d2, d1)
R@3   = 2/2 = 1.0
RR    = 1/1 = 1.0    (첫 정답 d2가 1등)

DCG@3  = (2¹−1)/log₂2 + 0/log₂3 + (2²−1)/log₂4 = 1/1 + 0 + 3/2 = 2.5
IDCG@3 = (2²−1)/log₂2 + (2¹−1)/log₂3         = 3/1 + 1/1.585 = 3.6309
nDCG@3 = 2.5 / 3.6309 = 0.6885
```

Hit@1, R@3, RR이 모두 만점인데 nDCG@3은 0.69다. 더 좋은 정답(d1, 2점)이 3등에 있고, 덜 좋은 정답(d2)이 1등에 있기 때문이다. 정답의 등급을 보는 지표만 이 차이를 잡는다.

## 5. 영어 rerank 14/15 vs hybrid 15/15

결과가 갈린 문항은 Q2 하나이고 hybrid가 맞혔다. 두 방식이 똑같이 좋다면 갈린 문항 하나가 hybrid 쪽일 확률은 **1/2 = 0.5**다. 동전 한 번 던진 결과와 같다. 「영어에서 재순위화가 해롭다」는 이 데이터로 말할 수 없다.

## 6. 설정 수를 2, 10, 50으로

[측정, 해설용 실험, 같은 씨앗]

| 설정 수 | 개발용 1등의 평균 점수 | 시험용에서 다시 잰 평균 |
| --- | --- | --- |
| 2 | 0.856 | 0.800 |
| 10 | 0.943 | 0.800 |
| 50 | 0.989 | 0.800 |

설정이 많을수록 개발용 1등 점수가 더 부풀려진다. 시험용 점수는 늘 진짜 실력(0.8)이다. 여러 번 던진 주사위 중 최댓값은 던진 횟수가 늘수록 커지는 것과 같다. 각 설정의 개발용 점수는 「진짜 실력 + 운」이고, 가장 높은 것을 고르면 운이 가장 좋았던 것을 고르게 된다. 50개를 비교하면 15문항 중 거의 다 맞히는(0.989) 설정이 거의 늘 하나쯤 나온다. **많이 시도할수록 개발용 점수를 덜 믿어야 한다.**
