# B. 전통적인 정보 검색: 문자열 일치에서 BM25까지

> BM25는 「질문의 낱말이 문서에 몇 번, 얼마나 드물게 나오는가」를 세는 공식이다. 공식의 각 부분은 바로 앞 방법이 실패한 이유 하나씩을 고치려고 붙었다.

이 장이 교재에서 가장 깊게 들어가는 장이다. 단계마다 「앞 방법이 어디서 깨지는가 → 무엇을 더해 고치는가」를 따라간다.

표시 규칙: **[측정]** 은 이 저장소에서 돌려 얻은 값, **[예시]** 는 설명용 값, **[기존 측정]** 은 앞선 장에 기록된 값이다.

## ① 학습 목표

- 문자열 일치 → 토큰화 → TF → IDF → TF-IDF → BM25로 넘어가는 이유를 각각 실패 사례로 설명한다.
- 문서 3개짜리 코퍼스에서 TF, DF, IDF, TF-IDF, BM25 점수를 손으로 계산한다.
- BM25의 `k1`과 `b`가 무엇을 조절하는지 숫자로 보이고, 둘을 0으로 두면 어떻게 되는지 예측한다.
- 한국어에서 띄어쓰기 토큰화가 왜 약하고, 형태소 분석과 n-gram이 각각 무엇을 대가로 그걸 고치는지 말한다.
- `bm25.py`를 보지 않고 같은 점수를 내는 BM25를 직접 짠다.

## ② 선수 지식

- [A장](A-before-rag.md): 코퍼스·문서·토큰, 역색인.
- 로그(ln)를 「곱셈을 덧셈으로 바꾸고, 큰 수를 천천히 키우는 함수」 정도로 알면 충분하다. ln 1 = 0, ln 2.718… = 1, 입력이 2배가 될 때마다 0.693씩 커진다.

## ③ 문제 상황

장난감 코퍼스 3편과 질문 하나로 시작한다. 손으로 계산할 수 있을 만큼 작게 만들었다 [예시].

```text
D1: 방화벽은 규칙에 따라 통신을 차단한다. 방화벽은 내부 네트워크를 지킨다.
D2: VPN은 통신을 암호화한다. VPN은 통신 내용과 통신 경로를 숨긴다. 공공 망에서 통신을 지킨다.
D3: 광합성은 햇빛으로 포도당을 만든다.

질문: 통신을 차단하는 방화벽
```

사람이 보면 답은 D1이다. D2는 「통신」을 여러 번 말할 뿐, 차단 이야기가 아니다. 일부러 그렇게 만들었다. 이 장의 모든 방법을 이 예제로 시험한다.

## ④ 가장 단순한 접근: 문자열 일치

질문 문자열이 문서 안에 그대로 있는지 본다. Python으로는 `query in text`, SQL로는 `LIKE '%...%'`다.

## ⑤ 실패 사례

실습 출력 [측정, `labs/basics/lexical.py`]:

```text
=== 1부. 문자열 일치 ===
D1: 질문 전체가 글에 그대로 있나? False
D2: 질문 전체가 글에 그대로 있나? False
D3: 질문 전체가 글에 그대로 있나? False
```

세 편 모두 실패다. 사람은 같은 말을 같은 순서, 같은 어미로 쓰지 않는다. 문자열 일치는 「정확히 이 문장」을 찾을 때만 쓸모 있다. 해결의 첫걸음은 문장을 **더 작은 단위로 쪼개서, 부분적으로 겹치는 것을 세는 것**이다.

## ⑥ 원리 설명

### 6.1 토큰화: 무엇을 「같은 낱말」로 볼 것인가

가장 쉬운 방법은 띄어쓰기와 문장 부호로 자르는 것이다.

```text
=== 2부. 띄어쓰기로 자르기 ===
질문 단어: ['통신을', '차단하는', '방화벽']
D1: 겹치는 단어 ['통신을']
D2: 겹치는 단어 ['통신을']
D3: 겹치는 단어 []
```

D1과 D2가 똑같이 한 단어씩 겹친다. 「방화벽」이 안 겹친 이유는 D1에는 「방화벽은」만 있어서다. 한국어는 낱말 뒤에 조사(은, 는, 을, 를 …)와 어미(-한다, -하는 …)가 붙는다. 이런 언어를 교착어라고 한다. 영어는 띄어쓰기만으로도 낱말이 꽤 잘 나뉘지만, 한국어는 그렇지 않다.

그래서 조사를 떼어 본다. 실습의 `strip_particles()`는 「은·는·을·를·에서·으로…」로 끝나면 떼는 아주 거친 규칙이다. 진짜 형태소 분석기가 아니다.

```text
=== 3부. 조사 떼기 + 단어 빈도(TF) ===
질문 토큰: ['통신', '차단하', '방화벽']
D1 (9개): ['방화벽', '규칙', '따라', '통신', '차단한다', '방화벽', '내부', '네트워크', '지킨다']
D2 (13개): ['vpn', '통신', '암호화한다', 'vpn', '통신', '내용', '통신', '경로', '숨긴다', '공공', '망에서', '통신', '지킨다']
D3 (4개): ['광합성', '햇빛', '포도당', '만든다']
```

「방화벽」이 이제 겹친다. 대신 규칙의 허점도 보인다.

- 「차단하는」은 「는」만 떨어져 「차단하」가 됐고, D1의 「차단한다」와는 여전히 다르다. 어미 변화(-한다, -하는, -했다)는 조사 목록으로 못 잡는다.
- 「망에서」는 남은 글자가 한 글자라 규칙(「떼고 나서 두 글자 이상 남을 때만」)에 걸려 안 떨어졌다.

이것이 형태소 분석기가 필요한 이유다(6.8). 지금은 이 거친 토큰으로 계속 간다.

### 6.2 단어 빈도(TF): 많이 말할수록 그 이야기다

토큰이 생겼으니 겹치는 것을 센다. **TF(term frequency)** 는 토큰 t가 문서 d에 나온 횟수다. 기호로는 tf(t, d)라 쓴다.

| 질문 토큰 | tf(·, D1) | tf(·, D2) | tf(·, D3) |
| --- | --- | --- | --- |
| 통신 | 1 | 4 | 0 |
| 차단하 | 0 | 0 | 0 |
| 방화벽 | 2 | 0 | 0 |
| **합** | **3** | **4** | **0** |

질문 토큰의 TF를 더하면 D2가 4로 이긴다.

```text
질문 토큰의 TF 합: {'D1': 3, 'D2': 4, 'D3': 0}
```

**실패다.** D2가 이긴 이유는 「통신」을 네 번 말했기 때문이다. 그런데 「통신」은 D1과 D2 모두에 있는 흔한 말이다. 「방화벽」은 D1에만 있다. 질문에서 어느 낱말이 문서를 가려 주는지를 TF는 모른다. 모든 낱말을 똑같은 무게로 센다.

### 6.3 문서 빈도(DF)와 역문서 빈도(IDF): 드문 낱말에 무게를

**DF(document frequency)** 는 토큰 t가 들어 있는 문서 수다. df(t)라 쓴다. 횟수가 아니라 문서 수다. D2에 「통신」이 네 번 나와도 df에는 1만 더한다.

- df(통신) = 2 (D1, D2)
- df(방화벽) = 1 (D1)
- 코퍼스의 문서 수 N = 3

df가 클수록 흔한 토큰이고, 흔한 토큰은 문서를 가려 주지 못한다. 모든 문서에 있는 토큰은 겹쳐도 아무 정보가 없다. 그래서 df에 반비례하는 무게를 준다. 이것이 **IDF(inverse document frequency)** 다. 교과서적인 형태는 다음과 같다.

```text
IDF(t) = ln( N / df(t) )
```

| 기호 | 뜻 |
| --- | --- |
| N | 코퍼스의 문서 수 |
| df(t) | 토큰 t가 들어 있는 문서 수 |
| N / df(t) | 「문서 몇 편에 한 편꼴로 나오나」의 역수. 드물수록 크다 |
| ln | 그 값을 천천히 키운다 |

손으로 계산해 보자.

```text
IDF(통신)  = ln(3 / 2) = ln 1.5 = 0.4055
IDF(방화벽) = ln(3 / 1) = ln 3   = 1.0986
모든 문서에 있는 토큰이라면 ln(3 / 3) = ln 1 = 0
```

**왜 ln을 씌우나?** 로그가 없으면 N = 1,000,000일 때 한 편에만 있는 토큰의 무게가 1,000,000이고, 두 편에 있는 토큰은 500,000이다. 한 편 차이로 무게가 두 배가 되고, 드문 토큰 하나가 점수를 독차지한다. ln을 씌우면 각각 13.8과 13.1이 되어, 「드물수록 크다」는 순서는 지키면서 차이는 완만해진다. 정보 이론에서는 df / N을 「아무 문서나 골랐을 때 그 토큰이 있을 확률」로 보고, −ln(확률)을 그 사건의 놀라움(정보량)이라 부른다. ln(N / df) = −ln(df / N)이니 IDF는 「그 토큰이 문서에 있다는 사실이 얼마나 놀라운가」다.

### 6.4 TF-IDF: 많이 × 드물게

둘을 곱한다. 문서 d의 점수는 질문 토큰 t마다 tf(t, d) × IDF(t)를 구해 더한 것이다.

```text
TF-IDF(D1) = 1 × 0.4055 (통신) + 2 × 1.0986 (방화벽) = 2.6027
TF-IDF(D2) = 4 × 0.4055 (통신)                     = 1.6219
TF-IDF(D3) = 0
```

실습 출력도 같다 [측정].

```text
=== 5부. TF-IDF = TF × IDF ===
D1: 1×0.4055(통신) + 2×1.0986(방화벽) = 2.6027
D2: 4×0.4055(통신) = 1.6219
D3: 0 = 0.0000
```

**D1이 이겼다.** D2의 「통신」 네 번은 흔한 낱말이라 0.4055씩만 받았고, D1의 「방화벽」 두 번은 드문 낱말이라 1.0986씩 받았다.

### 6.5 TF-IDF에 남은 두 가지 문제

**문제 1: 반복이 그대로 점수가 된다.** TF-IDF는 tf에 비례한다. 같은 낱말을 100번 쓴 문서는 1번 쓴 문서보다 100배 높은 점수를 받는다. 하지만 100번 쓴 문서가 100배 관련 있지는 않다. 낱말을 일부러 반복해 검색 순위를 올리는 수법(키워드 스터핑)도 여기서 먹힌다.

**문제 2: 긴 문서가 유리하다.** 긴 문서에는 어떤 토큰이든 우연히 들어갈 기회가 많고, tf도 커지기 쉽다. 주제와 상관없이 길기만 해도 점수가 오른다.

**문제 3 (변형에 따라): 음수 IDF.** BM25의 고전적인 IDF는 ln((N − df + 0.5) / (df + 0.5))다. 절반 넘는 문서에 있는 토큰이면 괄호 안이 1보다 작아져 IDF가 음수가 된다. 우리 예에서 df(통신) = 2, N = 3이면 ln(1.5 / 2.5) = −0.51이다. 그 토큰이 있으면 점수가 깎인다. 그래서 `bm25.py`를 포함해 많은 구현이 괄호 안에 1을 더한다.

```text
BM25의 IDF(t) = ln( 1 + (N − df(t) + 0.5) / (df(t) + 0.5) )
IDF(통신)  = ln(1 + 1.5 / 2.5) = ln 1.6    = 0.4700
IDF(방화벽) = ln(1 + 2.5 / 1.5) = ln 2.6667 = 0.9808
```

0.5는 df가 0이나 N일 때 0으로 나누거나 ln 0이 되는 것을 막는 보정이다. 15편 코퍼스에서 한 편에만 있는 토큰은 ln(1 + 14.5 / 1.5) = 2.367, 15편 모두에 있는 토큰은 ln(1 + 0.5 / 15.5) = 0.032다 [기존 측정, 3장].

### 6.6 BM25: 포화와 길이 보정

BM25는 TF-IDF의 문제 1과 2를 고친 공식이다. 토큰 t 하나의 몫은 다음과 같다.

```text
                      tf(t,d) × (k1 + 1)
IDF(t) × ────────────────────────────────────────────
          tf(t,d) + k1 × (1 − b + b × |d| / avgdl)
```

| 기호 | 뜻 | 보통 값 |
| --- | --- | --- |
| tf(t,d) | 토큰 t가 문서 d에 나온 횟수 | |
| \|d\| | 문서 d의 토큰 수(길이) | |
| avgdl | 코퍼스의 평균 문서 길이 | |
| k1 | 반복이 점수를 얼마나 더 올리는지. 클수록 TF-IDF에 가깝다 | 1.2~2.0 (`bm25.py`는 1.5) |
| b | 길이를 얼마나 보정할지. 0이면 안 함, 1이면 완전히 | 0.75 |

복잡해 보이지만 두 부품이다.

**부품 1, 포화(k1).** 길이가 평균인 문서(|d| = avgdl)라면 분모의 괄호가 1이 되어 식이 `tf × (k1 + 1) / (tf + k1)`로 줄어든다. k1 = 1.5로 계산하면 다음과 같다 [측정].

```text
  tf=  1: TF-IDF는 ×1     BM25는 ×1.000
  tf=  2: TF-IDF는 ×2     BM25는 ×1.429
  tf=  4: TF-IDF는 ×4     BM25는 ×1.818
  tf= 10: TF-IDF는 ×10    BM25는 ×2.174
  tf=100: TF-IDF는 ×100   BM25는 ×2.463
```

손으로 하나만 확인하자. tf = 2: 2 × 2.5 / (2 + 1.5) = 5 / 3.5 = 1.429. tf가 아무리 커도 `(k1 + 1) = 2.5`를 넘지 못한다. 첫 언급은 큰 신호, 두 번째는 작은 추가 신호, 백 번째는 거의 신호가 아니다. 사람이 문서를 읽을 때의 감각과 비슷하다.

**부품 2, 길이 보정(b).** 분모의 `|d| / avgdl`이 문서가 평균보다 몇 배 긴지다. 긴 문서일수록 분모가 커져 점수가 줄어든다. tf = 2, IDF = 1로 고정하고 길이만 바꾸면 다음과 같다 [측정].

```text
  평균의 0.5배 길이 → b=0.0: 1.429  b=0.75: 1.702  b=1.0: 1.818
  평균의 1배 길이 → b=0.0: 1.429  b=0.75: 1.429  b=1.0: 1.429
  평균의 2배 길이 → b=0.0: 1.429  b=0.75: 1.081  b=1.0: 1.000
  평균의 4배 길이 → b=0.0: 1.429  b=0.75: 0.727  b=1.0: 0.625
```

b = 0이면 길이를 무시한다. 평균 길이 문서는 b와 상관없이 같다. 같은 「방화벽 두 번」이라도 짧은 문서에서 나오면 그 문서가 방화벽 이야기일 가능성이 크고, 긴 문서에서 나오면 지나가는 말일 가능성이 크다. b는 이 직관을 얼마나 믿을지 정한다.

### 6.7 손으로 BM25 계산하기

장난감 코퍼스에 k1 = 1.5, b = 0.75로 적용한다.

**준비.** 글 길이는 D1 9, D2 13, D3 4토큰. avgdl = (9 + 13 + 4) / 3 = 8.6667.

**D1의 분모 상수.** K(D1) = k1 × (1 − b + b × |d| / avgdl) = 1.5 × (0.25 + 0.75 × 9 / 8.6667) = 1.5 × (0.25 + 0.7788) = 1.5433

```text
D1, 방화벽 (tf=2): 0.9808 × 2 × 2.5 / (2 + 1.5433) = 0.9808 × 1.4111 = 1.3841
D1, 통신   (tf=1): 0.4700 × 1 × 2.5 / (1 + 1.5433) = 0.4700 × 0.9830 = 0.4620
D1 합계                                                         = 1.8461
```

**D2의 분모 상수.** K(D2) = 1.5 × (0.25 + 0.75 × 13 / 8.6667) = 1.5 × (0.25 + 1.125) = 2.0625

```text
D2, 통신 (tf=4): 0.4700 × 4 × 2.5 / (4 + 2.0625) = 0.4700 × 1.6495 = 0.7753
D2 합계                                                       = 0.7753
```

실습 출력 [측정]:

```text
=== 6부. BM25 (k1=1.5, b=0.75) ===
글 길이 {'D1': 9, 'D2': 13, 'D3': 4}, 평균 8.6667
  D1 통신: tf=1, |d|=9 → 0.4620
  D1 방화벽: tf=2, |d|=9 → 1.3841
D1 합계: 1.8461
  D2 통신: tf=4, |d|=13 → 0.7753
D2 합계: 0.7753
```

TF-IDF(2.6027 대 1.6219, 1.6배)보다 BM25(1.8461 대 0.7753, 2.4배)에서 D1이 더 크게 이긴다. D2의 「통신」 네 번이 포화로 눌렸고(×4가 아니라 ×1.65), D2가 평균보다 길어서 한 번 더 깎였다.

### 6.8 한국어: 형태소 분석과 n-gram

6.1에서 남은 문제는 「차단하는」과 「차단한다」다. 두 길이 있다.

**형태소 분석기**는 문장을 뜻을 가진 가장 작은 단위(형태소)로 나누고 품사를 붙인다. 「차단하는」 → 차단(명사) + 하(동사 파생) + 는(어미). 그러면 「차단」끼리 겹친다. 정확하지만, 사전과 모델이 든 별도 프로그램(예: Elasticsearch의 nori, Kiwi, MeCab-ko 계열)이 필요하고, 사전에 없는 신조어와 고유명사에서 틀린다.

**n-gram**은 뜻을 모른 채 글자를 n개씩 겹쳐 자른다. 2-gram(두 글자 조각)이면 다음과 같다.

```text
차단하는 → 차단 단하 하는
차단한다 → 차단 단한 한다
```

「차단」이 겹친다. 사전이 필요 없고 신조어에도 동작한다. 실습 출력 [측정]:

```text
=== 6부 덧붙임. 두 글자 조각이면 「차단하는」과 「차단한다」가 만난다 ===
질문 두 글자 조각: ['통신', '신을', '차단', '단하', '하는', '방화', '화벽']
D1: 겹치는 조각 ['방화', '신을', '차단', '통신', '화벽']
D2: 겹치는 조각 ['신을', '통신']
```

대가도 있다.

- **우연한 일치.** 「갈수록」과 「지날수록」이 `수록`을 공유해, 인플레이션 질문이 복리 글 쪽으로 끌렸다 [기존 측정, 3장].
- **토큰 수가 늘어난다.** 글자 수만큼 조각이 생겨 색인이 커진다.
- **언어마다 맞는 단위가 다르다.** 영어를 두 글자로 자르면 뜻 없는 조각이 된다. G장 종합 실습에서 그 결과를 직접 확인한다.

### 6.9 실제 15편에서 토큰화를 바꿔 보면

장난감에서 실제로 넘어가 보자. 정답표 15문항으로 BM25만 돌리고 토큰화만 바꾼다 [측정, `lexical.py --real`].

```text
토큰화           ko    en
띄어쓰기        10/15  12/15
조사 떼기       13/15  12/15
두 글자 조각     14/15  12/15
```

- 한국어는 토큰화가 결과를 크게 바꾼다(10 → 14). 영어는 셋 다 12다. 영어는 띄어쓰기 단위가 이미 낱말이라 고칠 게 적다.
- 「두 글자 ko 14, en 12」는 3장에 버린 실험 코드로 잰 값으로 적혀 있었는데, 이번에 다시 재서 같은 값을 얻었다.

`k1`과 `b`도 바꿔 봤다(한국어, 두 글자 조각) [측정].

```text
  k1=0.5: b=0.0: 14/15  b=0.75: 13/15  b=1.0: 13/15
  k1=1.5: b=0.0: 13/15  b=0.75: 14/15  b=1.0: 14/15
  k1=3.0: b=0.0: 13/15  b=0.75: 13/15  b=1.0: 14/15
```

13과 14 사이를 오갈 뿐 뚜렷한 승자가 없다. 15문항에서 한 문항 차이는 운으로 생길 수 있다(F장). 이 표를 보고 「k1 = 0.5, b = 0이 최고」라고 고르면, F장에서 다룰 과적합이 된다. 기본값(1.5, 0.75)을 쓰는 것이 이 데이터에서는 정직한 선택이다.

### 6.10 전통적인 검색의 한계

BM25는 글자가 겹치는 것만 본다. 그래서 다음은 원리적으로 못 한다.

| 한계 | 예 | 어디서 다루나 |
| --- | --- | --- |
| 같은 뜻, 다른 글자 | 「햇빛을 전기로」 vs 「태양광 발전」. 겹치는 토큰 0 | C장 |
| 다의성 | 「배」(타는 배, 먹는 배) 둘 다 같은 토큰 | C장 |
| 순서 | 「개가 고양이를 쫓았다」와 「고양이가 개를 쫓았다」는 같은 토큰 묶음이다 | C장(임베딩도 약하다) |
| 부정 | 「차단한다」와 「차단하지 않는다」가 `차단`을 공유한다 | C장, E장 |
| 희소성 ≠ 중요성 | 작은 코퍼스에서는 뜻 없는 조각도 드물면 IDF가 커진다 | G장 |

그래도 BM25는 사라지지 않았다. 학습이 필요 없고, 고유명사·제품 코드·오류 메시지처럼 **정확히 같은 글자가 중요한 질문**에서 강하며, 왜 이 문서가 나왔는지 토큰별 점수로 설명할 수 있다. D장에서 임베딩과 섞어 쓰는 이유다.

**예상 결과**: 위 ⑤~⑥의 출력과 같고, 끝에 다음 두 줄이 나온다 [측정].

```text
이 파일의 BM25와 bm25.py의 점수 차이(15문항×15편 중 최대): 0.00e+00

모든 손 계산 검사를 통과했다.
```

**결과 해석**: 0.00e+00은 이 장에서 처음부터 짠 BM25가 저장소의 `bm25.py`와 225개 점수(15문항 × 15편) 모두에서 정확히 같다는 뜻이다. 이 장의 공식이 곧 저장소의 코드다.

**실패 조건**: 손 계산 값(예: TF-IDF(D1) = 2.6027, BM25(D1) = 1.8461)과 다르면 `AssertionError`가 그 줄에서 멈춘다. 공식을 고쳐 보는 실험을 할 때는 해당 `assert`를 먼저 새 예상값으로 바꾸자.

## ⑧ 기존 프로젝트와 연결

[`bm25.py`](../bm25.py)를 이 장의 기호로 읽으면 다음과 같다.

| `bm25.py` | 이 장의 기호 |
| --- | --- |
| `K1 = 1.5`, `B = 0.75` | k1, b |
| `tokenize()` | 6.8의 두 글자 조각. `lexical.py`의 `bigrams()`와 같은 규칙 |
| `self.docs = [Counter(...)]` | 문서마다 tf(t, d) 표 |
| `self.lengths`, `self.avg_length` | \|d\|, avgdl |
| `doc_freq = Counter(term for doc in self.docs for term in doc)` | df(t). `for term in doc`이 Counter의 키를 돌아서, 한 문서 안의 반복은 한 번만 센다 |
| `self.idf = {... math.log(1 + (n - df + 0.5) / (df + 0.5))}` | 6.5의 BM25 IDF |
| `saturation = K1 * (1 - B + B * length / self.avg_length)` | 6.7의 K(d) |
| `self.idf[term] * doc[term] * (K1 + 1) / (doc[term] + saturation)` | 6.6의 공식 그대로 |
| `for term in terms if term in doc` | 질문에 같은 토큰이 두 번 있으면 두 번 더한다 |

`retrieve.py`는 이 점수를 `hybrid()`에서 임베딩 점수와 섞는다(D장). 실제 15편에서의 결과와 오답 분석은 [3장](03-search.md)에 있다.

**이것을 제거하면?** `bm25.py`가 없으면 `--method hybrid`와 `rerank`가 dense만 남는다. 한국어 정답표 기준 Hit@1이 14/15에서 12/15로 떨어진다 [측정, `labs/score_fusion.py`의 「dense만」과 「min-max 0.7」].

## ⑨ 한계와 실무적 타협

| 교과서적 이상 | 실제 서비스 |
| --- | --- |
| 형태소 분석으로 정확한 토큰 | 형태소 분석 + n-gram을 함께 색인하기도 한다. 하나는 정확도, 하나는 신조어·오타 대비 |
| k1, b를 데이터에 맞게 튜닝 | 대부분 기본값을 쓴다. Lucene(Elasticsearch, OpenSearch)의 기본은 k1 = 1.2, b = 0.75다. 튜닝하려면 개발용·시험용 질문을 나눠야 한다(F장) |
| 모든 토큰을 공평하게 | 불용어(조사, the, a 같은 기능어)를 빼거나, 제목 필드에 가중치를 더 주기도 한다 |
| 문서 단위 점수 | 구(phrase) 검색, 근접도(토큰끼리 가까울수록 가산)를 더하기도 한다 |

데이터가 100배 늘면? BM25 계산 자체는 질문 토큰의 포스팅 길이에 비례하니 역색인을 쓰면 버틴다(A장). 대신 IDF가 코퍼스 전체에 의존하므로, 문서를 추가할 때마다 모든 토큰의 IDF가 조금씩 바뀐다. 실무 엔진은 IDF를 매번 다시 계산하지 않고 색인 조각(segment)별 통계를 합쳐 근사한다.
